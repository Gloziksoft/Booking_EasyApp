# Oracle Cloud Security List – Port Hardening

**Date:** 2026-09-27
**Environment:** Booking VM
**Hostname:** `booking-easyapp`
**Public IP:** `152.70.22.237`

## Context

During the initial development of the Booking application, several Docker service ports were exposed through the Oracle Cloud Security List to simplify access during development and testing.

At that time the main goal was to make the services easily accessible. Security and network segmentation were not yet fully understood.

The configuration was later reviewed following technical feedback from Jiří.

The goal was to keep the required public entry points while removing unnecessary direct access to internal application, monitoring and administration ports.

---

## Original public ingress

The Oracle Cloud Security List allowed direct access from:

```text
0.0.0.0/0
```

to several internal service ports.

The following ports were reviewed:

| Port | Service | Original state |
|---:|---|---|
| 8080 | Booking Spring Boot | Public |
| 8081 | cAdvisor | Public |
| 8082 | pgAdmin | Public |
| 9090 | Prometheus | Public |
| 3000 | Grafana | Public |
| 8083 | No listener | Public rule existed |

---

# 1. Port 8083

No service was listening on port `8083`.

The OCI Security List rule was therefore unnecessary and was removed.

**Result:**

```text
8083 → rule removed
```

---

# 2. Port 8080 – Spring Boot

The Booking application was listening on:

```text
0.0.0.0:8080
```

Direct access from the PC was verified before the change.

The application was also available through:

```text
https://bookingapp.gloziksoft.sk
```

through NGINX.

The OCI `8080` ingress rule was removed.

### Result

```text
Internet
   │
   └── :8080 ── X ──► Spring Boot
```

The application remains accessible through:

```text
HTTPS :443
     │
     ▼
   NGINX
     │
     ▼
localhost:8080
     │
     ▼
Spring Boot
```

# 3. Port 8081 – cAdvisor

On the Booking VM:

```text
8081 → cAdvisor
```

cAdvisor is required by Prometheus for container metrics.

Prometheus accesses cAdvisor internally through the Docker network:

```text
Prometheus
    │
    ▼
cadvisor:8080
```

The host port `8081` is therefore not required to be publicly accessible.

The OCI `8081` rule was removed.

### Result

```text
Internet ── X ──► VM:8081
```

cAdvisor continues to run internally.

For manual administration, cAdvisor can be accessed locally on the VM:

```text
http://127.0.0.1:8081
```

or through an SSH tunnel.

Because local port `8081` is already used by the local environment, an alternative local port can be used:

```bash
ssh -L 18081:localhost:8081 ubuntu@152.70.22.237
```

Then:

```text
http://localhost:18081
```

means:

```text
Local PC :18081
      │
      │ SSH tunnel
      ▼
Booking VM localhost:8081
      │
      ▼
cAdvisor
```

The local `localhost:8081` service on the PC remains untouched.

---

# 4. Port 8082 – pgAdmin

Port `8082` belongs to pgAdmin.

Before the change:

```text
http://152.70.22.237:8082/pgadmin/
```

was publicly accessible.

The service itself was verified locally:

```bash
curl -I http://127.0.0.1:8082/pgadmin/
```

Result:

```text
HTTP/1.1 302 FOUND
Location: /pgadmin/login?next=/pgadmin/
```

The OCI `8082` ingress rule was removed.

After the change, direct public access no longer worked.

However, the existing NGINX route continued to work:

```bash
curl -I https://bookingapp.gloziksoft.sk/pgadmin/
```

Result:

```text
HTTP/2 302
Location: /pgadmin/login?next=/pgadmin/
```

### Important distinction

Closing OCI port `8082` removed **direct public access**.

It did **not** remove the NGINX `/pgadmin/` route.

Therefore:

```text
Internet
   │
   ├── :8082 ── X ──► pgAdmin
   │
   └── :443
          │
          ▼
        NGINX
          │
          ▼
     localhost:8082
          │
          ▼
       pgAdmin
```

The public NGINX management route will be reviewed separately under **Jiří's Point 3**.

# 5. Port 9090 – Prometheus

Prometheus listens on:

```text
0.0.0.0:9090
```

Local health was verified:

```bash
docker exec prometheus wget -qO- http://localhost:9090/-/ready
```

Result:

```text
Prometheus Server is Ready.
```

The direct public endpoint was also tested before the change and responded.

The OCI `9090` ingress rule was removed.

After the change:

```text
127.0.0.1:9090
```

still responds:

```text
HTTP/1.1 405 Method Not Allowed
Allow: GET, OPTIONS
```

This is expected for the `HEAD` request generated by:

```bash
curl -I
```

The important point is that Prometheus remains running.

Direct public access:

```text
Internet ── X ──► :9090
```

is now blocked.

Prometheus continues to communicate internally with its monitoring targets.

# Final state after Point 2

The Oracle Cloud Security List no longer exposes the internal service ports directly to the internet.

Public ingress is reduced to:

```text
22   SSH

443  HTTPS
```

An internal `3306` rule from:

```text
10.0.0.0/16
```

also remains.

## Important lesson

A Docker service listening on:

```text
0.0.0.0:PORT
```

does not automatically mean that the service must be publicly accessible.

There are different layers:

```text
Internet
   │
   ▼
Oracle Cloud Security List
   │
   ▼
VM networking
   │
   ▼
Docker published port
   │
   ▼
Container
```

Removing an OCI ingress rule does not stop the container.

It removes the **public network path** to that port.

This allows internal services to continue running while reducing unnecessary public exposure.
